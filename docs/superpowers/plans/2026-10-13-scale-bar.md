# Scale Bar Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a dynamic distance scale bar (km) that updates on zoom/pan and renders in the bottom-left corner of the map viewport.

**Architecture:** A new `ScaleBar` presentational component reads `zoom` and `latitude` from `viewState` (already maintained in `App.tsx`) and derives bar width and label using the Web Mercator meters-per-pixel formula. It renders as an absolutely-positioned CSS ruler overlay with no background. `App.tsx` gains one import and one JSX line.

**Tech Stack:** React 19, TypeScript, inline styles (no CSS files). No test framework is present in this repo — verification is manual via `pnpm dev`.

**Spec:** `docs/superpowers/specs/2026-10-13-scale-bar-design.md`

## Global Constraints

- Inline styles only — no new CSS files, no CSS modules, no class names
- No new npm dependencies
- Units: km only
- `pointerEvents: none` on the scale bar element — must not block map interaction
- `pnpm check` (Biome lint + format) must pass before any commit
- Commit messages follow Conventional Commits: `feat(scale-bar): <description>` ≤ 72 chars, imperative mood
- Every commit includes trailer: `Co-authored-by: Claude <noreply@anthropic.com>`

## Review Focus

These are the edge cases the spec implies but manual verification in the golden path may not catch:

1. **Zoom too high (>16)** — `targetKm` falls below 1 km (below the ladder floor). Expected: bar shows "1 km" and stays visible, not NaN/zero width. Covered in Task 1, Step 3.
2. **Zoom too low (<2)** — `targetKm` exceeds 5000 km (above the ladder ceiling). Expected: bar shows "5000 km" and a finite pixel width. Covered in Task 1, Step 3.
3. **Latitude = 0 (equator)** — `cos(0) = 1`, maximum metersPerPixel; bar should be narrowest and still renderable. Covered in Task 1, Step 3.
4. **Latitude ≥ 85° (near pole)** — `cos(85°) ≈ 0.087`, metersPerPixel is tiny; bar width could overflow the viewport. Expected: clamps naturally via the ladder ceiling (5000 km at ~120 px). Covered in Task 1, Step 3.
5. **Both basemaps** — white bar/text with dark text-shadow must remain legible on both `dark` and `satellite`. Covered in Task 2, Step 4.

### Task 1: Implement `ScaleBar` component

**Files:**
- Create: `src/components/ScaleBar.tsx`

**Interfaces:**
- Consumes: nothing from other tasks
- Produces: `export function ScaleBar({ zoom, latitude }: { zoom: number; latitude: number }): JSX.Element`

- [ ] **Step 1: Create the file with the math helper**

Create `src/components/ScaleBar.tsx` with the following content in full:

```tsx
const EARTH_CIRCUMFERENCE = 2 * Math.PI * 6_378_137;
const KM_LADDER = [1, 2, 5, 10, 20, 50, 100, 200, 500, 1000, 2000, 5000];
const TARGET_WIDTH_PX = 120;

function computeScaleBar(
  zoom: number,
  latitude: number,
): { widthPx: number; label: string } {
  const metersPerPx =
    (Math.cos((latitude * Math.PI) / 180) * EARTH_CIRCUMFERENCE) /
    (256 * 2 ** zoom);
  const targetKm = (metersPerPx * TARGET_WIDTH_PX) / 1000;

  let niceKm = KM_LADDER[0];
  for (const km of KM_LADDER) {
    if (km <= targetKm) niceKm = km;
  }

  const widthPx = (niceKm * 1000) / metersPerPx;
  return { widthPx, label: `${niceKm} km` };
}

export function ScaleBar({
  zoom,
  latitude,
}: {
  zoom: number;
  latitude: number;
}) {
  const { widthPx, label } = computeScaleBar(zoom, latitude);
  return (
    <div
      style={{
        position: "absolute",
        bottom: 20,
        left: 20,
        zIndex: 1000,
        pointerEvents: "none",
        fontFamily:
          "-apple-system, BlinkMacSystemFont, 'Segoe UI', sans-serif",
        fontSize: "11px",
        color: "white",
        textShadow: "1px 1px 2px rgba(0,0,0,0.8)",
        userSelect: "none",
      }}
    >
      <div style={{ textAlign: "center", marginBottom: "3px" }}>{label}</div>
      <div
        style={{
          width: `${widthPx}px`,
          height: "6px",
          borderLeft: "2px solid white",
          borderRight: "2px solid white",
          borderBottom: "2px solid white",
          boxSizing: "border-box",
          filter: "drop-shadow(1px 1px 1px rgba(0,0,0,0.8))",
        }}
      />
    </div>
  );
}
```

- [ ] **Step 4: Start the dev server and verify visually**


Open `http://localhost:3000` and check each of the following:

1. **Zoom out to zoom ~3** (default view over boreal Canada) — scale bar appears bottom-left, label shows a round km value (e.g., "500 km" or "1000 km"), bar is ~60–120 px wide.
2. **Zoom in several levels** — label steps through the ladder (500 → 200 → 100 → 50 → …), bar width stays in the ~60–120 px range.
3. **Pan toward the equator** — at lower latitudes `cos(lat)` is larger, so `metersPerPixel` increases, `targetKm` increases, and `niceKm` may step up the ladder. The bar width stays roughly stable because `widthPx = niceKm × 1000 / metersPerPixel` self-corrects. Verify the bar shows a finite, positive width and a valid label at all latitudes.
4. **Toggle basemap to satellite** — white bar and label must remain legible against the satellite imagery.
5. **Switch to compare mode** — scale bar stays in bottom-left, does not overlap the `LayerPanel` controls or the divider handle.
